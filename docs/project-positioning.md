# 项目范围与实现场景

“vx agent接入”是一套 **VX 个人号自建 Agent 渠道参考**：
已有客户端和 Agent 各自运行，本项目负责连接，不重新实现 VX 协议、
通用 Agent 框架或云端语音模型。

## 两阶段

1. **文字基础版**：Linux VX 桌面客户端 + agent-wechat +
   OpenClaw channel 插件。按私聊或群组织会话，模型、角色、记忆、
   工具权限由 OpenClaw 维护。
2. **语音进阶版**：在基础渠道上增加 PulseAudio 和小智 Bridge，
   接入真实 VX 通话。语音语言、音色和角色由小智后台设置；
   文字/语音不会自动共享历史。

小智是当前后端；旧 Codex CLI Realtime / WebRTC 方案保留为研究与回退资料，
不与小智同时运行。本项目不承诺任意上游版本均可直接部署。

## 适合什么

- 家庭或好友可信群中的 AI 问答与低频聊天。
- 指定联系人的个人文字助手。
- 把已有 Agent 的文件、图片和工具能力接到日常聊天渠道。
- 使用专门测试号体验群语音智能体，或测试其他语音后端。
- 想理解架构、按自己设备逐层搭建的技术用户。

## 不适合什么

- 企业账号外部群、企业机器人接口或官方 API 替代方案。
- 面向陌生联系人无限制自动回复或自动接听。
- 高并发多通话、商业客服 SLA、无需维护的托管服务。
- 假定数据库读取成功即可绕过全部桌面依赖。
- 把一台现网机器的私有镜像、卷名和账号直接复制成通用安装包。

## 最少配置

- agent-wechat API 地址、token 文件及持久卷。
- 文字模型和 OpenClaw 人设/权限。
- 私聊白名单、群白名单、机器人显示名和 mention 规则。
- 可选主动观察群、冷却、每日次数上限。
- 语音版的小智设备身份、音频路由、后端选择。
- 主动拨号的群/成员映射，以及来电默认渠道。

接听窗口不能可靠提供群 ID；当前来电统一映射到指定渠道，不能
把文字白名单误当成语音接听白名单。需要严格区分群来电的部署不应直接启用。

## 实现边界

消息读取主要通过数据库与 REST API，打开聊天和发送依赖桌面控件。
通话控制也依赖桌面窗口；音频由 PulseAudio 采集并注入虚拟麦克风。
这些依赖必须明确管理，不靠无止境的补丁轮询掩盖故障。

旧的 entry watchdog、mention repair、cron delivery repair 等循环
已不属于当前默认安装内容；私人历史不在公开仓库中。

本仓库提供分步流程，不以“一键部署”为目标。验收重点是来自手机的
真实消息、真实语音、挂断清理和重启恢复，不是脚本退出码。
